## Problem Statement

小团队、多项目、任务拆分给不同负责人 + 协作人。费用(客户沟通费、订单样品费、物流费、域名/服务器费)目前**个人垫付**,记录靠**各人自己的 Excel**,后果:

1. 负责人(你)不知道钱花在哪、花了多少,"事后很久才告诉我"
2. 费用归不到正确项目(该 A 的记成 B,该分摊的记成单个项目)
3. 两人记同一笔,没有唯一性约束
4. 遗漏 + 补记靠回忆

载体是你们的 Leantime fork(`dev-self-hosted`)+ 自研 CostTracking 插件(任务上 planned/actual 成本字段,项目层汇总 vs 预算)。**插件功能已够用且保持现状,本次不写代码、不加字段。**

## Demand Evidence

- 真实痛点来自你自己(负责人)的日常:"我都不知道他们用了多少,用在哪里,他们也都是事后很久才告诉我"
- 有具体损失场景:费用归属错项目 / 重复记录,虽未造成算错预算(团队小、管理松),但信息不透明已持续发生
- 团队自用、自主决定,无外部审批关卡;痛点真实但不是"客户在付钱"级别

## Status Quo

- 各成员个人 Excel 记自己垫付的费用,没有统一归口
- 你作为负责人:部分项目不追费用,部分等汇报/催汇报
- 预算:你定/项目负责人定;分摊:口头规则"默认按相关项目平均分摊,手算完录入"
- 报销不在本系统,本系统只负责"记录下来 + 归属到项目"

## Target User & Narrowest Wedge

- **使用者**: 你团队的几名干活的人(协作人/任务负责人) + 你(负责人)
- **核心诉求**: 把"记一笔费用"做得足够轻、归属当场清楚,管理台(项目预算 vs 实际)自然长出来
- **最小交付(本次)**:
  1. **一份团队能执行的记账规矩**(谁记、何时记、哪类费用归哪个项目、分摊怎么手算、重复怎么防、负责人定期怎么核对)
  2. **一份 Leantime fork 的中文操作指南**(安装部署 → 建项目/任务 → CostTracking 插件使用 → 预算视图;弥补"网上只有英文文档"的缺口)

插件代码不动。规矩是数据与流程,指南是工具使用说明。

## Constraints

- 插件保持现状:不加字段、不加费用实体、不做系统级分摊自动化
- 团队小、管理松:规矩必须**可执行、低摩擦**,不能变成新的填报负担
- fork 策略"沿着 dev-self-hosted 走下去,不换不升级":指南按你们当前 fork 的实际界面写,不追上游
- 中文交付(用户要求后续对话与文档用中文)

## Premises

1. **要解决的是"费用归属混乱",不是"记录工具缺失"。** 记录字段已存在,病根是归属/重复/分摊无规矩。本次交付规矩而非功能。
2. **规矩写进文档与默认约定,不依赖你脑内记忆。** "默认平均分摊、手算完录入"固化为书面规则,团队都认。
3. **先让记录变轻、归属当场对,管理台后置。** 手下只为"记一笔"付努力,不为负责人仪表盘付努力;记录轻了数据才长出来。
4. **中文指南面向你们当前 fork 的界面,非上游文档翻译。** 用你们的部署配置(deploy/、Caddy/Docker/Railway/腾讯云)做基准。

### 交付物 1: `docs/cost-tracking-rules.md` — 记账规矩

**关键定义(先钉死,避免团队各解各的):**

- **经手人** = 实际下单或付款的那个人。一笔费用**只有一个**经手人,由他在自己负责的那张任务上记账。不是老板付的款就算老板,不是助理代下单就算助理——以"谁触发了这笔支出"为准,有争议时经手人当场群内 @ 相关人确认。
- **归属项目** = 这笔费用服务的是哪个客户/项目。如果这笔费用同时服务 ≥2 个项目(域名、服务器、团队共同采购),按**平均分摊**处理:算出每个项目的份额,在每个项目的对应任务上各记一笔 actual cost,备注写"分摊自{费用描述}"。
- **共同费用/内部开销** = 不服务任何客户项目的费用(办公采购、团队餐、纯内部工具)。这类费用归入一个专门的项目(建议叫"内部开销"或类似),经手人在该项目的任意一张固定"费用登记"任务上记账,不要散到各处。
- **垫付前不审批** = 现状是事后记录。本规矩不增加事前审批环节,只规范"发生后怎么记、归到哪、谁记"。

**记账节奏(低摩擦原则):**

- 产生即记: 经手人在**当周内**把这笔费用记到对应任务的 actual cost 上,备注写"日期 + 费用类型 + (可选)发票号"。补记必须标注"补记 + 原发生日期"。
- 负责人核对: **每周固定一天下午(默认建议周五,团队定后写死)**,你打开每个项目,在项目页面上找到与 **Details / Goals / Tasks 等并列的"成本"tab(CostTracking 插件挂的 tab,锚点 `#costtracking`,不在"项目设置"里)**,核对三件事:
  1. 本周是否有超预算项目(对比预算 bar 和 remaining)
  2. 是否有归属存疑的费用(备注不清晰或项目选错的)
  3. 是否有"补记"未消化的费用(时间戳和发生日期差很大)
- 任何异常当场在群里 @ 相关经手人改,不要攒到下周。

**Worked example(全流程走一遍):**

> 周一,你给 A 客户项目下单了一个样品,花 ¥200,你自己垫付了。
> 周二上午,你打开 Leantime → 进入 A 客户项目 → 找到你负责的那张任务(比如"A 客户 样品确认") → 点开任务 → CostTracking 的 "Actual cost" 字段填入 200 → 备注写 "09-02 样品费,垫付费,发票号 AB123"。
> 周五下午你核对时,该项目 Costs tab 里能看到这条 200,remaining 预算对应减少,归属项目=A 客户项目,无异常。

> 周一,你买了一台团队共用的服务器 ¥3000,服务 A、B 两个项目。
> 你算平均分摊: 1500 + 1500。
> 周二,你在 A 项目的对应任务上记 actual cost=1500,备注"服务器分摊 1/2,09-01 发票号";再进 B 项目对应任务记 1500,备注同理。周五核对时两个项目 Costs tab 各增 1500。

**防重复(两人记同一笔)的机制:**

- 唯一经手人原则: 一笔费用只有一个经手人(谁下单/付款谁记)。经手人不确定时,在群里 @ 相关人当场确认,不要两人各记各的。
- 每周核对: 你作为负责人看 Costs tab 时,**注意: 当前插件版本无法在界面上跨任务查看 free-text 备注,所以"发现重复"这一步在系统内实际做不到,只能靠周会口头对账**(各经手人报本周记了哪几张发票号,你当场听)。如果看到同一张发票号被报两次,让一人删掉、另一人留。
- **已知能力边界(本次不解决)**: 去重约束需要插件后续改动(加跨任务备注索引 / 发票号唯一性约束),本次纯文档交付不做。若团队真跑起来发现口头对账不够用,再立项做插件改动。

**内部开销项目(共同费用归属处)的维护规矩:**

- "内部开销"项目里放一张**固定的"费用登记"任务**,所有内部开销(办公采购、团队餐、纯内部工具)都记在这张任务上,不要散到各处。
- **这张任务不要删除或关闭**: 任务被删时 CostTracking 会级联删除该任务的成本行(`deleteForTicket`),累计金额就没了。若确需重建,先把历史累计手动记到新任务上,再删旧的。
- 新人第一次填时,该任务若还没有成本,在任务表里可能不可见(零成本任务默认隐藏),直接按任务名搜索"费用登记"找到它即可。

**费用类型 → 归属项目映射表(初始示例,团队需按真实费用清单补全后才能作为记账依据):**

> ⚠ 下表 5 行为**初始示例**,不是终稿。团队本周内必须按自己真实出现的费用类型补齐此表(尤其注意别漏了: 通信工具订阅费、差旅费、培训费、软件许可证、外部顾问费……),并加一行"其他费用 → 待定(经手人当场群内 @ 负责人裁定)"作为兜底。补全前,遇到表外类型一律走兜底行,不要硬塞进现有 5 类。

| 费用类型 | 归属规则 | 示例 |
|---|---|---|
| 客户沟通费 | 对应客户的当前项目 | A 客户拜访产生的打车/电话费 → A 项目任务 |
| 样品费 | 下单项目 | 给 A 客户做的样品 → A 项目 |
| 物流费 | 对应订单项目 | A 客户的发货运费 → A 项目 |
| 域名/服务器费 | 平均分摊到使用该服务的项目;纯内部归"内部开销" | 共两个项目的服务器 → 各 50% |
| 团队共同采购 | 归"内部开销"项目 | 办公文具、团队餐 |
| 其他(表外)费用 | 待定: 经手人当场群内 @ 负责人裁定归属,裁定结果补回本表 | 例: 某个新出现的订阅服务 |

(这张表是**本周内你们团队要填完整的**,不是示例终稿。)

- 影响: 计划的成功判据"一周内无两人记同一笔"实际上**不可验证**,这是 Codex 点出的最大洞。
- 选项:
  - A) 接受,在规矩文档里把"防重复"机制降级为"经手人原则 + 周会口头对账",并在 Open Questions 里明写"去重约束需后续插件改动,本次不做"
  - B) 保持现状(不写降级说明),等团队真跑起来发现做不到再说
  - C) 把"加一个跨任务备注去重视图"列为 P3 TODO,本次先按 A 写
- **Recommendation: A** — 诚实标注能力边界比假装能做到更好,而且这是规矩文档,团队读到了就会问"怎么看备注",不如先说清楚。

**组 2(事实修正):内部开销"固定费用登记任务"会被删 + 零成本任务在表里不可见**
- Codex 发现: 任务被删时 `deleteForTicket` 级联删成本行;且全量任务表里零成本任务被 `costtracking_enriched` 隐藏(除非已有成本)。所以"内部开销项目里放一张固定'费用登记'任务"这个设计,那张任务一旦被误删/关闭,所有累计数字就没了;另外新人第一次填,看不到成本列(因为还没填过),不知道往哪填。
- 选项:
  - A) 规矩文档加一条"内部开销项目的那张'费用登记'任务不要删,要重建时把历史累计手动搬过去"(低摩擦,靠人)
  - B) 接受 Codex 的建议:负责人先自己记 3 笔真实费用验证 rollup,再 onboarding 团队,顺序反过来
  - C) 两者都做
- **Recommendation: C** — A 是一条规矩(几乎零成本),B 是 Assignment 顺序调整(把"负责人先记 3 笔验证"放到"团队 30 分钟会"前面),两个不冲突,做 C 更稳。

**组 3(事实修正 + 依赖):补丁是 fork 内置的,不是用户任务;指南 §5 不该让用户 `git apply`**
- Codex 发现: fork 的 `deploy/entrypoint.sh` 已经内置 CostTracking submodule,`plugin_ensure.php` 在启动时同步插件;但中文指南 §5 写"安装与打 patch → 在任务上填...",这会把用户(团队成员)拉去做 fork 发布任务(`git apply`)。
- 选项:
  - A) 改指南 §5 为"CostTracking 已随 fork 部署内置,无需安装;如遇界面无成本 tab,清 `storage/framework/views/*` 缓存"(面向团队成员的真实操作)
  - B) 保留"安装与打 patch"步骤,面向的是"你自己部署 fork"的场景,不是团队成员
- **Recommendation: A** — 你的使用场景是"团队成员照指南操作",他们不需要打 patch;`git apply` 是 fork 维护者(你)的活,不放进给团队的指南里。
