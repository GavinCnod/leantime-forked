# 05 路由与控制器

## 5.1 双路由系统

所有请求**先试 Laravel 原生路由，未命中再回退旧 Frontcontroller**（[HttpKernel.php:195-217](app/Core/Http/HttpKernel.php#L195)）。

### 方式 A：Laravel 原生路由（新，推荐）

- 路由文件：`app/Domain/{X}/routes.php`，由 [RouteLoader.php](app/Core/Routing/RouteLoader.php) 自动加载（域路由 → 系统插件路由 → 用户插件路由），整组套 `CheckPermissions` 中间件。
- 目前仅 **5 个域**使用：Blueprints、Files、Projects、Setting、Users。示例：[Projects/routes.php](app/Domain/Projects/routes.php)（`/projects/projectImage/{id}` + 遗留 `/api/projects` 别名）、[Blueprints/routes.php](app/Domain/Blueprints/routes.php)（`/blueprints/{canvasSlug}/...` 路由组 + 旧 `/xxxcanvas/` 301 重定向）。
- 非 debug 模式下列表缓存在 `installation` cache store（`domainRoutes`）。

### 方式 B：Frontcontroller 约定式路由（旧，当前绝大多数请求走这里）

[Frontcontroller.php](app/Core/Controller/Frontcontroller.php)（503 行）约定：

```
/module/action                     → Domain\{Module}\Controllers\{Action}::get()|post()
/module/action/id                  → ... 带 id 参数（数字或 UUID）
/module/action/id/method           → ... 调用指定 method()
/hx/module/action/...              → Domain\{Module}\Hxcontrollers\{Action}
/api/module/action                 → Api 域控制器
```

- 解析顺序：Domain Controllers → Domain Hxcontrollers → Plugin Controllers → Plugin Hxcontrollers（[Frontcontroller.php:325-333](app/Core/Controller/Frontcontroller.php#L325)）。
- 空 URL 段回退 `dashboard.home` 默认路由。
- 控制器方法会注入 `$params`（合并 GET/POST），`$id` 识别数字或 UUID。
- 附带 `execute_action_start` / `execute_action_end` 事件与 `PermissionEnforcer` 挂钩。

> **二开建议**：新页面优先走方式 A（写 `routes.php` + 现代控制器）；简单/内部页面也可用方式 B 少写样板，但要接受它是"deprecated 但长期存在"的路径。

## 5.2 控制器两种写法（并存）

1. **旧式 `run()`**：单一方法内 `$_POST`/`$_GET` 分支处理 GET/POST（约 55 个控制器）。
2. **现代式 `get($params)` / `post($params)`**（约 83 个控制器）：按动词拆分、返回 `Response`、构造器依赖通过 `init()` 注入。**新代码一律用这种**。

控制器基类 [Core/Controller/Controller.php](app/Core/Controller/Controller.php)：
- 常用成员：`$this->tpl`（Template 单例）、`$this->language`、`$this->session`、`$this->auth`。
- 辅助：`redirect()`、`setResponseCode()`、`getJsonFromBody()`、`tpl->display(...)` 等。
- 页面渲染入口：`$this->tpl->display($viewName, $layoutName)`；HTMX 碎片用 `displayFragment()`。

## 5.3 HTMX 控制器（Hxcontrollers）

- URL 约定：`/hx/{module}/{action}/{method}/{id}`；带 `HX-Request` 头且非 modal/非 boosted 的请求也会路由到 Hxcontrollers（[Frontcontroller.php:190-203](app/Core/Controller/Frontcontroller.php#L190)）。
- 基类 [HtmxController.php](app/Core/Controller/HtmxController.php)：
  - `protected static string $view` 指向 Blade partial（如 `tickets::partials.milestoneCard`）；
  - 动作方法返回 fragment 名，`getResponse()` 渲染对应 section；
  - `$this->tpl->emit(HtmxTicketEvents::UPDATE)` 向响应 `HX-Trigger` 头写事件；
  - `init()` 做依赖注入（**不要用 `__construct`**）。
- 13 个域有 Hxcontrollers：Tickets（TicketCard/Subtasks/Milestones/TimerButton）、Projects、Timesheets（Stopwatch）、Widgets、Menu、Notifications、Plugins、Help、Dashboard、Goalcanvas、Comments、Wiki、Reports 等。
- 契约式组件 `HxComponent`（[HxComponent.php](app/Core/Controller/HxComponent.php)）：声明 `route()` / `swap` / `listensTo()` / `emits()`，配合 `<x-global::hx :for="ClassName" ...>` 挂载，事件契约由枚举单一来源，见 [06-模板与前端](06-模板与前端.md)。

## 5.4 路由中间件与权限

- Laravel 路由组默认挂 `CheckPermissions`（读取 controller@method 上的 `#[RequiresPermission]`）。
- Frontcontroller 路径由 `PermissionEnforcer` 在 `executeAction` 时检查同一属性。
- JSON-RPC 路径在 `Jsonrpc::executeApiRequest()` 内检查。
- 三个入口统一行为，见 [08-认证与权限](08-认证与权限.md)。

## 5.5 请求对象

- `IncomingRequest` / `ApiRequest` / `HtmxRequest` 三态自动识别（[RequestTypeDetector](app/Core/Http/RequestTypes)）。
- `HtmxRequest` 额外：`isBoosted()`、`getTarget()`、`getTriggerName()`、`getPrompt()` 等。
- 控制器方法签名里可直接类型注入 `IncomingRequest $request`（现代写法），旧的读 `$_GET`/`$_POST` 超全局（旧式 run()）。

## 5.6 URL 生成

- 模板中统一用 `{BASE_URL}` 占位 + `BASE_URL` 常量（应用根）。
- 视图渲染路径如 `tickets::showAll`（域命名空间）或 `global::components.xxx`（共享）。
- 生成绝对 URL 用 `BASE_URL` 拼接，注意子目录部署（`LEAN_APP_DIR`）。
