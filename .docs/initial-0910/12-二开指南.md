## 12.2 新增一个功能模块

**方案 A（推荐，走现代栈）**：

1. 建目录 `app/Domain/{X}/`：`Controllers/`、`Services/`、`Repositories/`、`Models/`、`Templates/`、`Permissions/`、`Hxcontrollers/`、`Htmx/`（按需）。
2. 写 `routes.php` 注册 Laravel 路由（套 `CheckPermissions` 中间件自动生效），控制器继承 `Core\Controller\Controller`，用 `get($params)/post($params)` 方法。
3. Service 继承 `Core\Domains\BaseService`，业务方法加 `@api` 注解与 `#[RequiresPermission]`。
4. 模板放 `Templates/`，用 `<x-global::*>` 组件，引用命名空间 `{x}::viewName`。
5. 建权限类 `Permissions/{X}Permissions.php` 并跑 `permissions:sync --seed`。

**方案 B（快速，走约定路由）**：只需 `Controllers/{Action}.php` + 模板，URL 自动是 `/{x}/{action}`（Frontcontroller）。适合内部页面/简单 CRUD，但不要用于新公共 API。

**最小控制器示例**（现代式）：

```php
namespace Leantime\Domain\X\Controllers;

use Leantime\Core\Controller\Controller;
use Leantime\Domain\X\Services\XService;

class ShowAll extends Controller
{
    private XService $xService;

    public function init(XService $xService): void { $this->xService = $xService; }

    public function get($params): void
    {
        $this->tpl->assign('items', $this->xService->getAll());
        $this->tpl->display('x::showAll');
    }
}
```

## 12.3 暴露 API

后端：在 Service 类加公开方法并写 `@api` docblock（[Jsonrpc.php:354-371](app/Domain/Api/Controllers/Jsonrpc.php#L354) 只放行带 @api 的方法）：

```php
/**
 * 列出所有 X
 *
 * @api
 */
public function getAll(): array { ... }
```

调用：`POST /api/jsonrpc`，body `{"jsonrpc":"2.0","method":"leantime.rpc.x.xService.getAll","params":{},"id":1}`。前端可用 [jsonrpcClient.js](app/Domain/Api/Js/jsonrpcClient.js)。

**权限检查**：方法上加 `#[RequiresPermission(permission: XPermissions::VIEW, projectIdParam: 'projectId')]`，或方法体内 `$this->authorize(...)` / `$this->can(...)`。

## 12.4 新增权限

1. 在 `app/Domain/{X}/Permissions/{X}Permissions.php` 声明常量（实现 `ProvidesPermissions`）：
   ```php
   public const string CREATE = 'x.create';
   ```
2. 在 `DefaultRolePermissions` 的 GRANTS 矩阵中为各角色加授权（按 level 递进 union 的增量规则）。
3. 执行 `php bin/leantime permissions:sync --seed`（幂等；`--prune` 清理孤儿）。

## 12.5 事件监听与定时任务

1. 在域内建 `register.php`（若不存在）：
   ```php
   use Leantime\Core\Events\EventDispatcher;

   EventDispatcher::add_event_listener(
       'leantime.domain.tickets.services.tickets.quickAddTicket.ticket_created',
       fn ($payload) => /* 你的逻辑 */
   );
   ```
2. 定时任务：监听 `leantime.core.console.consolekernel.schedule.cron` 事件向 Laravel Schedule 注册（参考 [app/Domain/Queue/register.php](app/Domain/Queue/register.php)）。
3. 新事件建议写成类式事件（`app/Domain/{X}/Events/{Y}.php` 实现 `LeantimeEvent`），在 Service 中 `TicketCreated::dispatch(payload)` 触发（参考 [TicketCreated.php](app/Domain/Tickets/Events/TicketCreated.php)）。

## 12.6 数据库变更

1. 新装结构：改 [SchemaBuilder.php](app/Domain/Install/Services/SchemaBuilder.php) 对应 `createXxxTable()`（或加新方法并在 `createAllTables()` 注册）。
2. 老库升级：在 [Install.php:45](app/Domain/Install/Repositories/Install.php#L45) 的 `$dbUpdates` 追加版本号（如 `31000`）并实现 `update_sql_31000()`。
3. 同时更新 `AppSettings::$dbVersion`（如 `3.10.0`）。
4. ⚠️ 不要创建 Laravel migration 文件——项目没有 migration 机制。
5. ⚠️ 涉及画布共享表时遵循 fail-closed 鉴权模式。

## 12.7 新增前端交互

1. **静态组件**：`app/Views/Templates/components/{name}.blade.php` → `<x-global::{name}>`（参考 [statTile.blade.php](app/Views/Templates/components/statTile.blade.php) 与 [COMPONENTS.md](app/Views/Templates/components/COMPONENTS.md)）。
2. **局部刷新**：Hxcontrollers 继承 `HtmxController`，`protected static string $view = '{x}::partials.xxx'`；模板用 `<x-global::hx :for="ClassName" :id="..." />` 挂载（懒加载默认 `revealed`）。
3. **事件联动**：域枚举 `Htmx/{X}Events.php` 定义 `lt:{x}:{entity}.{verb}`；服务端 `$this->tpl->emit(Enum::CASE)`；前端 `hx-trigger="lt:... from:body"`。
4. **JS**：`app/Domain/{X}/Js/{x}Controller.js` 挂 `leantime.{x}Controller`，构建后进 `compiled-app`。
5. **样式**：用 CSS 变量（`--accent1` 等），Tailwind 类用 `tw-` 前缀；深色模式自动适配。
6. 构建：`npx mix --production`。

## 12.8 新增 MCP 工具

```php
namespace Leantime\Domain\X\Tools;

use Laravel\Mcp\Server\Tool;
use Laravel\Mcp\Server\Tools\ToolInputSchema;
use Laravel\Mcp\Server\Tools\ToolResult;

class DoSomethingTool extends Tool
{
    public function __construct(private XService $service) {}
    public function name(): string { return 'doSomething'; }
    public function description(): string { return '...'; }
    public function schema(ToolInputSchema $schema): ToolInputSchema { return $schema->string('arg')->required(); }
    public function handle(array $arguments): ToolResult { /* 调用 service + 鉴权 */ }
}
```

放到 `app/Domain/{X}/Tools/` 即被自动发现。只读工具加 `#[IsReadOnly]`。

## 12.9 外观定制

- 颜色/字体/圆角：覆盖 `public/theme/{default,minimal}/css/{light,dark}.css` 的 CSS 变量；或用户端 UI 设置（写入 session 的 accent 覆写）。
- 新建主题：复制 `public/theme/default` → `public/theme/{name}/`，改 `theme.ini`（name、primaryColor、secondaryColor、colorModeSupport、colorPickerSupport）+ css。
- Logo：`LEAN_LOGO_PATH` / `LEAN_PRINT_LOGO_URL` 或设置页上传。
- 前端代码中不要硬编码颜色值（深色模式/主题切换会破）。

## 12.10 代码约定与易踩的坑

### 约定（源自 [CLAUDE.md:763-801](CLAUDE.md#L763)）
1. Controller 只调 Service；Service 校验输入、抛异常（`LeantimeException` 家族）。
2. 日期时间一律 `CarbonImmutable` / `dtHelper()`；DB 存 UTC `YYYY-MM-DD HH:MM:SS`。
3. 日志用 `Log::facade`（禁止 `error_log()`）。
4. 新配置进 `DefaultConfig.php` + `sample.env`（`LEAN_*`），Laravel 配置进 `laravelConfig.php`（不是 config/*.php）。
5. 方法/类都要 phpDoc；RPC 方法必须 `@api`。
6. 不需要向后兼容（除非明确要求）——不保留死代码。
7. 新代码尽量严格类型。

### 易踩的坑（本项目特有）
1. **别建 migration 文件** —— 项目没有迁移机制，改表走 SchemaBuilder + $dbUpdates。
2. **会话角色必须存名字符串** —— `session('userdata.role')` 是角色名（`editor`），不是数字（3.9.x 回归事故）。
3. **canvas 表共享 id 序列** —— 画布代码必须按实体真实项目鉴权，别信 `session('currentProject')`。
4. **CSRF 未全局启用** —— 表单安全靠自己（现代控制器建议手动校验或等待全局方案）。
5. **改前端必须构建** —— `public/dist` 不入库，不构建则线上没有新 JS/CSS。
6. **submodule app/Plugins 不要 init** —— OSS 二开用不到，且是私库。
7. **`artisan config:publish` 等命令不可用** —— 配置集中在 laravelConfig.php。
8. **Bearer token 是自研格式**（sha256 存库），别当标准 Sanctum token 用。
9. **API 方法名大小写敏感**：`leantime.rpc.{module}.{service}.{method}` 需与类名/方法名精确匹配（小写模块名/Studly 服务名/小写方法名）。
10. **新事件优先类式事件**，但保留 legacy 字符串双发，避免破坏既有插件监听。
11. **发布版本要双改**：`AppSettings::$appVersion` 与 `package.json` 的 version。
12. **环境变量是最终真相**：`LEAN_*` 环境变量 > `.env` > 默认值；排查配置问题时先看环境。

## 12.11 推荐的二开起步路线

1. 读完本套文档的 [02-架构总览](02-架构总览.md) 与 [05-路由与控制器](05-路由与控制器.md)，跑通本地环境（[11-构建测试与部署](11-构建测试与部署.md) §11.2）。
2. 顺着一个简单请求追踪代码：浏览器打开一个看板页 → 找 `Tickets/Controllers/ShowKanban.php` → Service → Repository → 模板，理解完整链路。
3. 挑一个小需求练手（如新增一个统计接口），实践 12.3/12.4 的流程。
4. 需要改动核心框架时先查 [CLAUDE.md](CLAUDE.md) 对应章节——它维护了最新的迁移状态和设计意图。
