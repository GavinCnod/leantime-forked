# 04 数据层

## 4.1 建表与升级机制（没有 Laravel migrations！）

本项目**不使用** Laravel Migration 文件（`database/` 目录只有 `.gitignore`）。数据库结构由两处管理：

1. **全新安装**：[Install/Services/SchemaBuilder.php](app/Domain/Install/Services/SchemaBuilder.php)（1015 行）用 Laravel Schema Builder 以数据库无关方式创建全部 35 张表（同时支持 MySQL 与 PostgreSQL），并插入初始数据（公司、管理员、默认角色/权限、设置等）。
2. **版本升级**：[Install/Repositories/Install.php](app/Domain/Install/Repositories/Install.php)（3264 行）维护 `$dbUpdates` 数组（如 `30408` = 3.4.8 的更新），按当前 `dbVersion` 逐个执行 `update_sql_xxxx()` 方法，完成后更新 `zp_settings` 里的版本号。

> **二开改表结构**：不要创建 migration 文件！正确做法是：
> 1. 修改 `SchemaBuilder` 中的 `createXxxTable()`（保证新装用户拿到新结构）；
> 2. 在 `Install/Repositories/Install.php` 的 `$dbUpdates` 末尾追加新版本号（如 `31000`）并实现对应 `update_sql_31000()` 增量脚本（老库升级用）。

## 4.3 Repository 模式

- 基类：[Core/Db/Repository.php](app/Core/Db/Repository.php)（继承自 Laravel Query Builder 包装）、数据库抽象 [Core/Db/Db.php](app/Core/Db/Db.php)。
- 混用 Laravel Query Builder 与少量原生 SQL（越新代码越偏 Query Builder）。
- `dbcall()` 方法在 SQL 执行前后派发事件（可被插件拦截/审计）。
- 跨数据库兼容辅助：[Core/Db/DatabaseHelper.php](app/Core/Db/DatabaseHelper.php)（MySQL/PostgreSQL/MSSQL）。

## 4.4 Model 模式

- 领域 Models（如 [Tickets/Models/Tickets.php](app/Domain/Tickets/Models/Tickets.php)）是**简单数据结构**：public 属性 + `mixed` 类型，非 ORM 实体，无注解、无校验。
- 部分使用 `#[DbColumn('列名')]` 属性做列映射。
- 新代码建议在"需要结构化"时新建 Model/DTO（[Core/Domains/DTO.php](app/Core/Domains/DTO.php)），而非裸数组。

## 4.5 日期时间约定（重要）

- 数据库内所有日期：**UTC，`YYYY-MM-DD HH:MM:SS`**。
- 前端/用户输入：用户所在时区与格式。
- 代码中一律使用 `CarbonImmutable` 或 `dtHelper()`（[Core/Support/DateTimeHelper.php](app/Core/Support/DateTimeHelper.php)），内置多种常见格式解析宏。**不要**用 `Carbon` 可变实例或裸 `date()`。

## 4.6 缓存

- Laravel cache（file 或 Redis），`installation` cache store 承载领域相关缓存（域路由清单、权限映射、插件列表等）。
- `do_once($key, $callback, $across_requests)` 辅助函数做单次执行。
- 修改权限/插件后注意 `flushCache()`。
