# 11 构建、测试与部署

## 11.1 环境要求速查

- PHP 8.2+（扩展清单见 [01-项目概览](01-项目概览.md) §1.5）
- MySQL 8+ / MariaDB 10.6+ / PostgreSQL
- Node ≥ 18（构建前端）
- Composer 2

## 11.2 本地开发环境

推荐 Docker（`make` 目标，见 [makefile](makefile) 与 [.dev/](.dev/)）：

```bash
make clean build        # 首次构建开发环境
make run-dev            # 启动，Leantime:8090 / MailDev:8081 / phpMyAdmin:8082 / S3Ninja:8083
```

手动方式：
```bash
make install-deps-dev   # npm install + composer install
make build-dev          # npx mix（带 source map）+ node generateBlocklist.mjs
```
- web 根目录指向 `public/`
- `cp config/sample.env config/.env` 并配置数据库 → 浏览器访问 `/install` 走安装向导

## 11.3 构建产物与版本管理

| 命令 | 说明 |
|---|---|
| `npx mix` | 开发构建（source map） |
| `npx mix --production` | 生产构建 |
| `node generateBlocklist.mjs` | 生成 CSP 等安全相关的 blocklist.json |

- 输出到 `public/dist/`（**整个目录 gitignore**，仅 `mix-manifest.json` 入库）。
- **改任何 JS/CSS/领域 JS 后必须重新构建**，否则提交不包含前端变更；CI/部署流程中也需要先构建。
- 版本号来源：`AppSettings::$appVersion`（php 侧）与 `package.json:3`（npm 侧），发布前两者需同步。

## 11.4 CLI 命令

入口 `php bin/leantime`（[bin/leantime](bin/leantime)，Laravel Artisan 风格自定义封装）。命令用 `#[AsCommand]` 特性声明，由 ConsoleKernel 自动发现（`app/Command/` + `app/Domain/**/Command/` + 启用插件的 Command/，[ConsoleKernel.php:110-157](app/Core/Console/ConsoleKernel.php#L110)）。

| 命令 | 用途 |
|---|---|
| `user:add` | 新增用户 |
| `db:migrate`（别名 `db:install`/`db:update`） | 数据库安装/升级 |
| `db:backup` | 数据库备份 |
| `permissions:sync [--seed] [--prune]` | 同步权限词汇表 |
| `auth:create-bearer-token --email=...` | 签发 API Bearer Token |
| `system:update` | 升级安装 |
| `plugin:install / enable / disable / remove / list` | 插件管理 |
| `setting:save [key] [value]` | 保存系统设置 |
| `email:testemail` | 测试邮件配置 |
| `goals:backfillHistory` | 回填目标历史 |
| `files:cleanup` | 清理孤儿文件 |
| `cache:clearAll` / `language:clear` | 清缓存 |
| `event:check-listeners` / `translations:check-unused` | 开发辅助 |
| `env:sync` | LEAN_* 写回 .env（疑似未接线） |

## 11.7 部署选项

1. **Docker**（官方镜像 leantime/leantime）：数据卷需挂载 `app/Plugins`（否则插件随容器重建丢失）、`userfiles`、`config`。
2. **传统 LAMP**：web 根 = `public/`（Apache 用根目录 `.htaccess`；Nginx 参考 [nginx.example.conf](nginx.example.conf)、子目录参考 [nginx-subfolder.example.conf](nginx-subfolder.example.conf)；IIS 用 `web.config.sample`）。
3. **Kubernetes**：`helm/` chart（注意 `app.session.expiration` 与 `LEAN_SESSION_EXPIRATION` 单位一致，均为分钟）。
4. **fork 自建镜像（[deploy/](../deploy/)）**：`deploy/Dockerfile.prod` 从源码构建（Node 阶段产出 dist，PHP 8.3-fpm-alpine + nginx + supervisord），`deploy/docker-compose.prod.yml` 为单机生产编排（PostgreSQL + Redis + Caddy，命名卷持久化），`deploy/entrypoint.sh` 为容器入口。

### 11.7.1 持久化卷与内置插件同步（重要）

`app/Plugins` 在生产中是持久化挂载点（Compose 命名卷 `plugins:/var/www/html/app/Plugins`；Railway 单卷模式则软链到 `/data/plugins`）。Docker 卷**只在首次为空时用镜像内容初始化一次**，之后重新 build/部署镜像，卷里的旧内容都会遮蔽镜像中的插件目录——这会导致随源码发布的本地插件（如 CostTracking）在容器里不可见。

fork 镜像对此的处理（2026-09 起）：

1. 构建时把源码插件快照复制到镜像内 `/opt/leantime/plugins.builtin/`（见 Dockerfile.prod）；
2. [entrypoint.sh](../deploy/entrypoint.sh) 每次启动把快照**幂等同步**进运行时插件目录（只新增/覆盖同名内置插件，不删除市场安装的插件），随后修正属主；
3. 需要在无 shell 平台（Railway）自动安装启用插件时，设置环境变量：
   `LEAN_PLUGINS_ENABLE=mindrose/costtracking`（逗号分隔多个包名），entrypoint 会在启动 web 前调用 [deploy/plugin_ensure.php](../deploy/plugin_ensure.php) 幂等安装启用（未注册才装、未启用才启），并对数据库未就绪做最多 60 秒重试。

因此**新增随镜像发布的插件后，只需重新构建/部署镜像，无需手工进容器拷贝**。

### 11.7.2 Railway 部署要点

- Docker 服务选择仓库根目录构建、Dockerfile 路径填 `deploy/Dockerfile.prod`。
- 挂载一个 Volume 到 `/data`，并设环境变量 `LEAN_PERSIST_ROOT=/data`：entrypoint 会把 `userfiles`、`public/userfiles`、`app/Plugins`、`storage` 软链到卷内（Railway 每服务仅一个卷）。
- 数据库建议用 Railway 托管的 PostgreSQL/MySQL，通过 `LEAN_DB_*` 变量连接（不要把数据库放进同一容器的 /data）。
- 需要启用内置插件时加 `LEAN_PLUGINS_ENABLE=<composer 包名列表>`；Railway 没有 docker exec 入口，插件安装/启用只能靠该机制（或首次手工部署临时入口，不推荐）。
- 插件启用状态在数据库 `zp_plugins` 中持久化，卷里只存插件文件；二者都持久化后，后续部署无需任何手工动作。

## 11.8 升级路径

- 新装：`/install` 向导 → SchemaBuilder 全量建表。
- 升级：检测到 `AppSettings::$dbVersion` 高于库中版本 → `Install\Repositories\Install` 按序执行 `$dbUpdates` 增量脚本 → 更新版本号。
- 曾有个坑：php-mcp 包替换后残留的 `bootstrap/cache/packages.php` 会导致启动崩溃，仓库内置了兼容 shim（[Core/Shims/McpServiceProvider.php](app/Core/Shims/McpServiceProvider.php)）——升级类二开不要删它，除非确认无人从 ≤3.9.6 原地升级。
