# 02 技术方案

## 2.1 总体架构

完全遵循 Leantime 官方插件模型（见 [.docs/initial-0910/07-事件与插件.md](../initial-0910/07-事件与插件.md) §7.2），插件由四块组成：

```text
┌────────────────────────────────────────────────────────────────┐
│  composer.json            元数据，安装器据此登记 zp_plugins      │
│  Services/CostTracking.php PluginInterface：建表/删表生命周期    │
│  register.php             启用后被 include：装配全部事件/过滤器  │
│  Repositories/Costs.php   自有表的数据访问 + 实时汇总            │
│  Templates/*.blade.php    视图命名空间 costtracking::            │
│  Language/*.ini           en-US / zh-CN                         │
└────────────────────────────────────────────────────────────────┘
           │ 只通过官方扩展点交互，不覆盖任何核心类
           ▼
┌─────────────────────── 核心（Leantime core）────────────────────┐
│ Tickets 服务（TicketCreated/Updated/Deleted、TicketListFilter）  │
│ Tickets/Projects 模板（@dispatchEvent 钩子）                     │
│ zp_tickets / zp_projects（只读 join，不修改结构）                │
└─────────────────────────────────────────────────────────────────┘
```

**请求期加载链路**：HTTP 请求 → `LoadPlugins` 中间件 → 取已启用插件 → `include_once app/Plugins/CostTracking/register.php`（[EventDispatcher.php:538-586](../../app/Core/Events/EventDispatcher.php#L538-L586)）→ 闭包监听器注册到 EventDispatcher → 核心在既有位置派发事件/过滤器时被调用。

类自动加载无需额外配置：根 `composer.json` 的 PSR-4 是 `"Leantime\\": ["app/"]`，所以 `app/Plugins/CostTracking/...` 自动映射到 `Leantime\Plugins\CostTracking\...`。

## 2.2 数据表设计

插件自有表，install 时由 Laravel Schema 建立（[Services/CostTracking.php](../../app/Plugins/CostTracking/Services/CostTracking.php)）：

```sql
CREATE TABLE zp_ticket_costs (
    ticketId   INT                NOT NULL,   -- = zp_tickets.id（1:1，不加外键约束）
    cost       DECIMAL(12,2)      NULL,       -- 预算成本
    actualCost DECIMAL(12,2)      NULL,       -- 实际成本
    modified   DATETIME           NULL,       -- 最近写入时间（UTC，gmdate）
    PRIMARY KEY (ticketId)
);
```

设计要点：

- **主键即外键语义**：`ticketId` 1:1 对应 `zp_tickets.id`，upsert 天然幂等。刻意不加数据库外键——插件卸载 `DROP TABLE` 时无需处理约束，删除任务时也由插件监听器主动清理。
- **可空**：两金额均可 `NULL`，与「未估算/未发生」语义对应；清空表单写回 `NULL` 而不是 `0`，合计时 `SUM` 与展示层都按 null 跳过。
- **表前缀 `zp_`**：与核心表一致（前缀是安装时配置的，默认 `zp_`；插件当前直接使用默认前缀，多前缀部署需改造，见 [05-持续开发指南.md](05-持续开发指南.md) §5.6）。
- 建表用的是核心引导好的 Laravel 数据库连接，因此 MySQL/MariaDB/PostgreSQL 的方言差异由 Schema Builder 吸收。

## 2.3 Repository 接口

[Repositories/Costs.php](../../app/Plugins/CostTracking/Repositories/Costs.php) 注入核心 `Leantime\Core\Db\Db`，取其 `ConnectionInterface`（与核心 Repository 同一连接，同一事务上下文）：

| 方法 | 用途 | 调用点 |
|---|---|---|
| `upsert(int $ticketId, ?float $cost, ?float $actualCost): bool` | 按 ticketId insert/update | TicketCreated / TicketUpdated 监听器 |
| `deleteForTicket(int $ticketId): void` | 删任务时清理 | TicketDeleted 监听器 |
| `getForTicket(int $ticketId): ?array` | 单条取数（表单回填、卡片角标） | 表单注入、看板角标 |
| `getAllTicketCosts(): array<int,array>` | 全表成本 map（请求内只查一次并缓存） | TicketListFilter 批量富化 |
| `getProjectRollup(int $projectId, string $scope): array` | 单项目汇总 | 项目成本 Tab |
| `getAllProjectRollups(string $scope): array<int,array>` | 一次查全部项目汇总（请求内缓存） | 项目集卡片，避免 N+1 |

汇总返回结构统一为：

```php
['cost' => 0.0, 'actualCost' => 0.0, 'ticketCount' => 0]
```

### 两种汇总口径（SQL）

汇总查询 join `zp_tickets` 取 `projectId` 并按任务类型过滤。类型归一化表达式：

```sql
COALESCE(NULLIF(t.type, ''), 'task')
```

因为历史数据中普通任务的 `type` 可能是 `''` 或 `NULL`，直接 `t.type <> 'subtask'` 会把 `NULL` 行误排除，必须先归一化。

| 口径常量 | 过滤条件 | 语义 |
|---|---|---|
| `SCOPE_TOPLEVEL`（默认） | `NOT IN ('subtask','milestone')` | 独立/顶层任务，含普通任务 |
| `SCOPE_SUBTASKS` | `= 'subtask'` | 仅子任务 |

合计用 `COALESCE(SUM(...), 0)`，计数用 `COUNT(c.ticketId)`（即「含成本记录的任务数」）。

> 注意：口径只控制**任务类型**，不判断 `dependingTicketId`。核心数据约定里子任务的判定字段就是 `type='subtask'`；两个口径互斥，相加 = 全部非里程碑任务成本，因此同口径内绝无父子双算。

### 请求级缓存

`$ticketCostMap` / `$projectRollupMap` 是实例属性缓存：项目集一页渲染几十张卡片只触发一次汇总 SQL。任何写操作（upsert/delete）会把缓存置空，保证同请求内先写后读也不脏。Repository 以 `app(Costs::class)` 从容器取，默认单例，缓存实际覆盖整个请求。

## 2.4 事件 / 过滤器挂载地图

全部装配在 [register.php](../../app/Plugins/CostTracking/register.php)：

| 核心扩展点 | 类型 | 插件回调职责 |
|---|---|---|
| `TicketCreated::class` | 类式事件 | 新任务后 upsert 成本（事件带新 id） |
| `TicketUpdated::class` | 类式事件 | 编辑保存后 upsert；**ticketId 为 null 的批量事件自动跳过** |
| `TicketDeleted::class` | 类式事件 | 删除插件表对应行 |
| `TicketListFilter::class` | 类式过滤器 | 批量给分组任务行附加 `costtracking_cost` / `costtracking_actual_cost`，**必须 return payload** |
| `beforeEndRightColumn`（模板事件） | 字符串事件 | 在任务表单右栏底部渲染两个输入框 |
| `allTicketsTable.afterHeadCell`（**新增核心钩子**） | 模板事件 | showAll 在核心表头行内追加两个成本 `<th>`（保持单行、与行尾 `<td>` 对齐） |
| `allTicketsTable.beforeRowEnd` | 模板事件 | showAll 行尾追加两个成本 `<td>` |
| `allTicketsTable.afterTitleCell`（**新增核心钩子**） | 模板事件 | showList 在标题格内追加金额角标（与任务名同行） |
| `allTicketsTable.afterClose` | 模板事件 | 表格下方渲染分组合计条 |
| `ticketCard.meta`（**新增核心钩子**） | 模板事件 | 看板/Htmx 任务卡片金额角标 |
| `projectTabsList` / `projectTabsContent` | 模板事件 | 项目设置页注入「成本」Tab |
| `projectCard.afterProgress`（**新增核心钩子**） | 模板事件 | 项目集卡片总成本 |
| `leantime.*.afterLinkTags` | 通配字符串事件 | 注入一段自包含 `<style>`，免前端构建 |
| `Registration::registerLanguageFiles(['en-US','zh-CN'])` | Registration API | 注册语言文件（先英文后用户语言覆盖） |

### 类式事件/过滤器的调用约定（易踩坑）

- 类式**事件**监听器收到的是**类型化对象本身**：`function (TicketUpdated $event) { $event->ticketId; }`（[EventDispatcher.php:209-232](../../app/Core/Events/EventDispatcher.php#L209-L232)）。
- 类式**过滤器**签名是 `function ($payload, $filterObject)`，`$payload` 就是分组数组，处理完**必须 return**（[EventDispatcher.php:264-302](../../app/Core/Events/EventDispatcher.php#L264-L302)）。
- `TicketListFilter` 的载荷**不是一维任务数组**，而是分组结构：

```php
[
  'all' => ['label'=>'all', 'id'=>'all', 'value'=>'', 'class'=>'', 'items'=> [ ...行... ]],
  // groupBy 非 all 时会有多个分组
]
```

监听器必须遍历每个 group 的 `items`。
- 每个类式事件还会双发一个 legacy 字符串事件名（`legacyHooks()`），本插件只监听 FQCN，不会与 legacy 路径重复执行。

### 模板事件的回调签名与载荷

`@dispatchEvent('x', ['ticket'=>$row])` 派发后，**监听器回调只收到一个数组实参**，即派发载荷并入 `current_route` / `currentEvent` 后的结果，原始键保持在顶层：

```php
[
  'ticket'        => $row,
  'current_route' => '...',
  'currentEvent'  => 'leantime.domain.tickets.templates.showall.allTicketstable.afterHeadCell',
]
```

回调必须写成**单参数**：

```php
EventDispatcher::add_event_listener('leantime.*.beforeEndRightColumn', function (array $payload): void {
    $ticket = costtracking_context($payload, 'ticket');
});
```

> ⚠️ 不要写成 `function ($event, $wrap)` + `$payload = $wrap[0] ?? []`。核心 `executeHandlers()`（[EventDispatcher.php:418](../../app/Core/Events/EventDispatcher.php#L418)）虽然形式上是 `$parsedListener($event, [$payload['leantime']])`，但闭包经 `makeListener()`（[EventDispatcher.php:702-708](../../app/Core/Events/EventDispatcher.php#L702-L708)）展开为 `$listener(...array_values(...))`，最终**只传一个参数**；第二个形参恒为 `null`，`$wrap[0] ?? []` 会被 `??` 静默吞成 `[]`，监听器看似触发实则什么都不渲染。断言见 [EventDispatcherCharacterizationTest.php:87-108](../../tests/Unit/app/Core/Events/EventDispatcherCharacterizationTest.php#L87-L108)。

模板事件的「事件名 + 载荷」都从这一个参数里取：`$payload['currentEvent']` 即完整事件名（插件封装为 `costtracking_event()`）。`costtracking_context()` 先试 `$payload[$key]`，对 `leantime`/`laravel` 子键的回退仅是防御式写法，事件监听器实际不会遇到嵌套。

**区分同名钩子在哪个模板触发**：模板事件名带 hook context，例如

```text
leantime.domain.tickets.templates.showall.allTicketstable.beforeRowEnd
leantime.domain.tickets.templates.showlist.allTicketstable.beforeRowEnd
leantime.domain.tickets.templates.showallmilestones.allTicketstable.beforeRowEnd
```

插件用 `costtracking_event()` 取 `currentEvent` 转小写后 `str_contains` 判断（context 由 [Template.php:984-993](../../app/Core/UI/Template.php#L984-L993) 的 `setHookContext()` 生成，规则为 `leantime.domain.{module}.templates.{path}`）。

## 2.5 保存链路：为什么不会被「看板拖拽/快速建任务」清空

核心 Tickets 服务保存任务时用字段白名单组装 values，插件的两个 POST 字段不会进核心 update；插件靠自己的事件监听器写自有表。但核心在很多场景都会派发 `TicketUpdated`：

| 场景 | 是否带插件字段 | 期望行为 |
|---|---|---|
| 完整新建/编辑表单提交 | 是 | upsert 两个值（空串→NULL） |
| 顶部快速建任务（quickadd） | 否 | **不动成本** |
| 看板拖拽改状态/排序 | 否 | **不动成本** |
| 行内改计划工时、截止日期 | 否 | **不动成本** |
| 批量排序 | 否，且事件 `ticketId=null` | **不动成本** |

`$saveCosts` 闭包的两道闸：

```php
if ($ticketId === null || $ticketId <= 0) return;                         // 闸 1：无具体任务
if (!array_key_exists('costtracking_cost', $_POST)
    && !array_key_exists('costtracking_actual_cost', $_POST)) return;     // 闸 2：本表单没渲染插件字段
```

第二道闸用 `array_key_exists` 而不是 `!empty`——字段存在但值为空串正是「用户主动清空」，必须写回 NULL。

数值清洗 `costtracking_amount()`：`''`/null → null；去空格；兼容逗号小数点；`is_numeric()` 校验，非法值按 null 处理（不抛错、不阻断核心保存）。

> 权限安全：核心在 create/update/delete **权限校验通过之后**才派发这些事件，插件监听器不自行做授权，天然继承核心权限。

## 2.6 列表富化与 DataTables 列冲突（本插件最关键的工程决策）

### 问题

showAll 的 `.ticketTable` 由 DataTables 1.13 初始化（[ticketsController.js:1561](../../app/Domain/Tickets/Js/ticketsController.js#L1561)），并且核心 JS **写死了列索引**：

- `columnDefs` 隐藏列 10/11（计划工时、剩余工时）；
- `footerCallback` 对列 9/10/11/12 做合计。

如果按常规思路在每行**开头**插入两个 `<td>`，所有核心列右移 2 位，排序/隐藏/工时合计全部错位；在 `tfoot` 加单元格还会引发 DataTables 列数告警。

### 方案：行尾追加 + 表头原位追加

- **数据行**：监听 `beforeRowEnd`（位于 `<tr>` 内、核心最后一个 `<td>` 之后、`</tr>` 之前），在**行尾**输出 2 个 `<td>`。核心列索引 0–13 完全不变，插件列是 14/15。
- **表头**：核心没有「表头行内部」的现成钩子——`beforeHeadRow` 落在 `<tr>` **之前**、`afterHeadRow` 落在 `</tr>` **之后**，都无法进入同一行（早前版本用 `beforeHeadRow` 输出「14 占位 + 2 标题」的补充行，结果是在核心表头上方多出一整行，且 DataTables 列模型错乱）。为此在 showAll 核心表头行的最后一个 `<th>` 之后新增一行钩子 `allTicketsTable.afterHeadCell`（见 [03-改动清单.md](03-改动清单.md) A4），插件在此追加 2 个 `<th>`。表头保持**单行 16 格**，与 body 的 16 格一一对齐。
- **合计不放 `<tfoot>`**：核心 tfoot 只有 14 格且被 `footerCallback` 占用，插件改为监听 `afterClose` 在 `</table>` **外面**渲染一条合计栏，绕开 DataTables 对表格内部 DOM 的接管。

### showList 为什么不用同样方案

简易列表（showList 的 `.listStyleTable`）每行只有 2 个单元格（状态、标题，表头行还是 `display:none` 的），没有可对齐的列尾语义。该视图的 `beforeRowEnd` 落在标题 `</td>` **之后**，直接输出 `<div>` 会变成 `<tr>` 的直接子节点，被浏览器 foster-parent 移出表格（表现为角标聚成表格外的一坨，无法对应任务）。为此在 showList 标题 `<td>` 内新增钩子 `allTicketsTable.afterTitleCell`（见 [03-改动清单.md](03-改动清单.md) A5），插件在标题 `<a>` 之后输出**行内** `inlineBadge`（`<span>` + `inline-flex`），与任务名同一行、不新增列、不影响 DataTables。

### 里程碑表格的三重防护

`showAllMilestones` / `showAllMilestonesOverview` 复用同一套 `allTicketsTable.*` 事件名，但里程碑行：

1. **不经过 `TicketListFilter`**（过滤器只在 Tickets 服务的两个任务列表派发），行上永远没有 `costtracking_*` 键 → `costtracking_enriched()` 返回 false；
2. 监听器再用 `currentEvent` 上下文包含 `milestone` 做显式跳过；
3. 表头注入只认 `templates.showall.` 上下文。

因此里程碑表格的列结构保持原样。

## 2.7 看板/项目卡片

- 看板与 Htmx 任务卡片都派发新钩子 `ticketCard.meta`，载荷 `['ticket'=>$row]`。监听器按 id 查单条成本（命中 Repository 请求缓存），两个值都为 null 时不输出任何 HTML。
- 项目卡片在 `projectCard.afterProgress` 输出。监听器调 `getAllProjectRollups()` 一次拿全部项目汇总再按 id 取，整页 N 张卡片只有 1 条 SQL；成本全为 0 的项目不渲染。
- 所有模板事件渲染都包了 try/catch（`costtracking_render()`），渲染异常只记日志，不打挂核心页面（核心本身也会捕获模板事件异常并 `report()`）。

## 2.8 项目成本 Tab 与口径切换

- 核心 [showProject.blade.php](../../app/Domain/Projects/Templates/showProject.blade.php) 本就有 `projectTabsList`（`<ul>` 内）和 `projectTabsContent`（tab 容器内）两个钩子，插件分别输出 `<li><a href="#costtracking">` 和 `<div id="costtracking">`，jQuery tabs 自动识别，无需 JS。
- 项目 id 取 `session('currentProject')`：`ShowProject` 控制器渲染前已把该项目写入 session（[ShowProject.php:66](../../app/Domain/Projects/Controllers/ShowProject.php#L66)），比解析 URL 可靠。
- 口径切换不做自定义路由，就是两个普通链接：
  `…/projects/showProject/{id}?costScope=toplevel#costtracking` 与 `…?costScope=subtasks#costtracking`。监听器读 `$_GET['costScope']`，白名单限定 `toplevel|subtasks`，其他值一律回落到 `toplevel`。
- 面板展示：预算合计、实际合计、项目预算、剩余/超支、使用率（实际/预算，进度条超 100% 变红）、含成本任务数；项目预算为 0 时显示「去项目详情设置预算」提示而非除零。

## 2.9 视图、样式与语言

- **视图命名空间**：`ViewsServiceProvider::discoverViewPaths()` 自动扫描 `app/Plugins/*/Templates` 并以目录名小写注册（[ViewsServiceProvider.php:427-445](../../app/Core/UI/ViewsServiceProvider.php#L427-L445)），模板里用 `costtracking::partials式名`（本插件模板都在 Templates 根，故为 `costtracking::tableCells` 等）。该发现结果会缓存到 `storage/framework/viewPaths.php`，安装插件后核心的 `plugin:install` 会自动清缓存。
- **样式**：一段 `<style>` 经通配事件 `leantime.*.afterLinkTags` 输出到 `<head>`，不依赖 Mix manifest 与 `dist/`。颜色全部引用核心 CSS 变量（`--danger`、`--secondary-background` 等）并带 fallback，自动适配深色模式。
- **语言**：INI 文件**不使用段落头**，key 直接带插件前缀（如 `costtracking.planned_cost = "..."`），模板中 `__('costtracking.planned_cost')`；`Registration` 会先合并 en-US 再用当前用户语言覆盖。语言解析结果被 installation 缓存 7 天，改 INI 后需清缓存（见 04 文档）。写段落头会导致解析成嵌套数组、`__()` 找不到平铺 key 而把词缀原样显示，详见 [05-持续开发指南.md](05-持续开发指南.md) §5.11 坑 3。

## 2.10 关键权衡小结

| 选择 | 放弃的方案 | 原因 |
|---|---|---|
| 自有表 1:1 | 给 `zp_tickets` 加列 | 插件可干净卸载；不碰核心迁移 |
| 实时 SUM | 项目表冗余汇总 + 增量维护 | 无一致性维护成本，数据量下性能足够 |
| 事件监听写库 | 覆盖 Tickets 服务/控制器 | 升级核心时冲突面最小 |
| 行尾追加列 | 行首插列 / 覆盖整个列表模板 | DataTables 核心列索引写死，行尾零影响 |
| 表外合计条 | tfoot 加单元格 | 避开列数冲突与核心 footerCallback |
| 内联 `<style>` | 注册 CSS 走 Mix | 插件无构建产物也能跑 |
| GET 链接切口径 | 自定义路由+控制器 | 少一层维护，满足只读切换 |
