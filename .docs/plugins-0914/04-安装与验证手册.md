# 04 安装与验证手册

## 4.1 前置条件

- 已部署可运行的 Leantime fork（PHP 8.2+ / MySQL 8 或 MariaDB 10.6+）。
- `app/Plugins/CostTracking/` 已随代码就位（本 fork 已解除子模块绑定，正常 pull/clone 即有）。
- 执行 CLI 的用户对数据库有 CREATE TABLE 权限（install 时建插件表）。

## 4.2 安装与启用

### 方式一：CLI（推荐）

在项目根目录执行：

```bash
php bin/leantime plugin:install leantime/costtracking
php bin/leantime plugin:enable leantime/costtracking
```

> ⚠️ **命令参数是 composer 包名，不是目录名**。CLI（`AbstractPluginCommand::getPlugin()`）拿参数与 composer.json 的 `name` 字段（`leantime/costtracking`）严格比较，传目录名 `CostTracking` 会报 `Invalid plugin name: CostTracking`。目录名只在服务层 `installPlugin()` 内部经 `Str::studly()` 推导类名时使用。
> 脚本/CI 等非交互环境追加 `--no-interaction`（非交互下确认提示默认视为 yes）。

- install 做两件事：读取 `composer.json` 在 `zp_plugins` 登记插件；调用 `Services\CostTracking::install()` 创建 `zp_ticket_costs`。
- enable 后插件进入启用列表，`LoadPlugins` 中间件开始 include `register.php`。
- install/enable 内部都会调用插件服务的 `clearCache()`（清 installation 缓存与视图路径缓存），正常无需手工清缓存。
- 插件发现靠**扫描磁盘** `app/Plugins/*`。Docker 部署时若代码是构建进镜像而非挂载卷，必须先把插件文件同步进容器（重新 build / git pull / docker cp），否则同样报 Invalid plugin name。可用 `ls app/Plugins/CostTracking` 确认。

其他管理命令：

```bash
php bin/leantime plugin:list                            # 查看插件及启用状态
php bin/leantime plugin:disable leantime/costtracking   # 停用（保留表与数据）
php bin/leantime plugin:remove leantime/costtracking    # 卸载（调 uninstall() 删表并移除登记）
```

### 方式二：管理界面

1. 以管理员登录 → 插件管理页。
2. 本地文件夹插件若未出现在列表，点一次「发现新插件 / Discover」（底层 `discoverNewPlugins()` 扫描 `app/Plugins/*`）。
3. 点击安装 → 启用。

### 方式三：持久化卷 / Railway 等无 shell 平台（自动）

生产容器的 `app/Plugins` 是持久化卷（Compose 命名卷，或 Railway `LEAN_PERSIST_ROOT=/data` 下的软链）。Docker 卷只在首次为空时跟随镜像，之后会**遮蔽镜像里的插件目录**，导致重新部署后 `ls app/Plugins/CostTracking` 为空、CLI 报 `Invalid plugin name`。

fork 镜像已内建处理机制（详见 [.docs/initial-0910/11-构建测试与部署.md](../initial-0910/11-构建测试与部署.md) §11.7.1）：

1. 构建镜像时插件被快照到 `/opt/leantime/plugins.builtin/`；
2. entrypoint 每次启动把快照幂等同步进卷（只覆盖同名内置插件，不影响市场插件）；
3. 设置环境变量后还会自动安装并启用：

```bash
LEAN_PLUGINS_ENABLE=leantime/costtracking
# 多个插件逗号分隔：leantime/costtracking,leantime/xxx
```

**Railway 操作步骤**：

1. 服务变量中确认 `LEAN_PERSIST_ROOT=/data`，且 Volume 挂载到 `/data`；
2. 新增变量 `LEAN_PLUGINS_ENABLE=leantime/costtracking`；
3. 用新镜像（包含本插件与该机制的提交）触发一次 Redeploy；
4. 部署日志中依次出现：
   `syncing built-in plugins into /data/plugins` →
   `[plugin:ensure] leantime/costtracking: installed (...)` →
   `[plugin:ensure] leantime/costtracking: enabled` →
   `plugins ensured`。

首次执行时若数据库尚未就绪，entrypoint 会每 2 秒重试、最多 60 秒；重试耗尽只告警、不阻断 web 启动（下次部署/重启会自动补上）。安装启用状态在数据库中持久化，之后的部署即使保留该变量也只是输出 `already registered / already enabled`，无副作用；插件稳定后也可以删掉该变量（文件同步始终生效）。

> Compose 命名卷环境同理：重建镜像并 `up -d` 后文件自动同步，可不设 `LEAN_PLUGINS_ENABLE`，仍进容器执行方式一的两条命令；不想进容器则同样设置该变量（写入 `deploy/.env`）。
> 老版本镜像（2026-09-14 机制合入前部署的）没有自动同步，临时方案是 `docker compose cp app/Plugins/CostTracking app:/var/www/html/app/Plugins/` 后手工安装。

## 4.3 安装结果核对

### 数据库

```sql
SHOW TABLES LIKE 'zp_ticket_costs';
DESCRIBE zp_ticket_costs;
-- 期望 4 列：ticketId(int,PRI) / cost(decimal 12,2,YES) / actualCost(同) / modified(datetime,YES)

SELECT * FROM zp_plugins WHERE foldername = 'CostTracking';
-- 期望存在一行，enabled = 1
```

### 文件/缓存

- 若页面没有任何插件输出，先清编译视图与 installation 缓存：

```bash
rm -rf storage/framework/views/*                 # Blade 编译缓存
rm -f  storage/framework/viewPaths.php           # 插件视图命名空间发现缓存
php bin/leantime cache:clear                     # 若该命令可用
```

- 语言文件结果被 installation 缓存 7 天，**修改 INI 后**必须清缓存（或直接走管理后台的清缓存）。

## 4.5 常见问题

**Q：安装后页面看不到任何成本 UI？**
A：按顺序排查：① `plugin:list` 是否 enabled；② 清 `storage/framework/viewPaths.php` 与 views 编译缓存；③ 模板事件渲染异常会被记日志，看 `storage/logs/laravel.log` 中 `[CostTracking]` 记录。

**Q：点保存后成本没存上？**
A：① 确认是从完整表单提交（字段 `name` 必须是 `costtracking_cost` / `costtracking_actual_cost`，勿改名）；② 查 `zp_ticket_costs`；③ 批量操作事件 `ticketId=null` 会被有意跳过，属正常。

**Q：任务全表列错位 / 控制台 DataTables 警告？**
A：说明补充表头行未输出或被其他插件改动。确认 `tableHeaderExtra.blade.php` 渲染出的 `<tr>` 恰好 16 个 `<th>`、body 每行恰好 16 个单元格；该方案依赖「核心 14 列不变」，若核心升级改了列数，需同步调整占位数量（见 05 文档 §5.4）。

**Q：改了 ini 语言没生效？**
A：语言解析结果被 installation 缓存 7 天，清缓存后刷新。

**Q：PostgreSQL 能用吗？**
A：建表走 Schema Builder，汇总用的是 `COALESCE`/`NULLIF` 标准 SQL，理论兼容；当前主要在 MySQL/MariaDB 验证，PG 上请重点回归汇总查询。

**Q：本机没有 PHP 怎么验证语法？**
A：开发机若未安装 PHP/未启动 Docker，可在部署/CI 环境执行：

```bash
php -l app/Plugins/CostTracking/register.php
php -l app/Plugins/CostTracking/Services/CostTracking.php
php -l app/Plugins/CostTracking/Repositories/Costs.php
```

**Q：全新环境 clone 后 `app/Plugins` 变成空目录或报子模块错误？**
A：说明该环境仍保留旧 `.gitmodules` 或用了旧提交。确认拉取的是已删除 `.gitmodules` 的提交；若之前执行过 `submodule init`，先 `git submodule deinit -f app/Plugins` 并删除 `.git/modules/app/Plugins`。

**Q：容器内 `ls app/Plugins/CostTracking` 不存在，安装报 Invalid plugin name？**
A：持久化卷遮蔽了镜像插件目录（见 §4.2 方式三）。使用 2026-09-14 之后的镜像重新部署，entrypoint 会自动把内置插件同步进卷；Railway 等无 shell 平台再设置 `LEAN_PLUGINS_ENABLE=leantime/costtracking` 即可自动安装启用。老镜像的临时救急：宿主机执行 `docker compose -f deploy/docker-compose.prod.yml cp app/Plugins/CostTracking app:/var/www/html/app/Plugins/` 后进容器安装。
