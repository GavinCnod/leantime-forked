## B. `.gitmodules` 两次变更：先解除官方子模块，再将插件独立成库并挂回

### B0. 历史（第一步）：解除 upstream 的 `app/Plugins` 官方子模块

upstream 曾把 `app/Plugins` 登记为指向官方商业插件私库的 git 子模块：

```ini
# 原 .gitmodules（已删除）
[submodule "app/Plugins"]
	path = app/Plugins
	url = git@github.com:Leantime/plugins.git
```

后果：Git 把整个 `app/Plugins` 当作一个 submodule gitlink，**插件文件无法加入主仓库提交**（`git add` 报 `Pathspec ... is in submodule 'app/Plugins'`）；且该私库无推送权限，子模块方式对自建 fork 不可行。

当时已执行的操作（可复现）：

```powershell
# 1. 从索引移除子模块指针（保留磁盘文件，不要加 -f）
git rm --cached app/Plugins

# 2. 删除 .gitmodules（本仓库只有这一个子模块；若有其他子模块则只删除对应小节）
Remove-Item .gitmodules   # 本次操作等价于删除该文件

# 3. 清理 .git/config 中的子模块配置小节
git config --remove-section submodule.app/Plugins

# 4. 把变为普通目录的插件与 .gitmodules 删除一并暂存
git add app/Plugins .gitmodules
```

说明：

- 子模块本地从未 init 检出（`git submodule status` 前缀为 `-`，目录下无 `.git`），所以不需要 `git submodule deinit`，也无需清理 `.git/modules/app/Plugins`。
- `.gitignore` **没有**忽略 `app/Plugins`（仅有一条不相关的 `app/custom/plugin/`），解除后目录内文件直接由主仓库跟踪。此步骤让插件一度作为 fork 的普通文件提交。

### B1. 现状（2026-09-14 起）：插件迁出为独立仓库，以子模块挂回

插件不再作为 fork 的普通文件维护，而是拆到独立仓库，单一真源在插件仓库：

- 插件仓库：<https://github.com/GavinCnod/mr-leantime-costtracking>（composer 包名 `mindrose/costtracking`）
- 仓库**根目录即插件根**（`composer.json`/`register.php`/`Services`/… 在根），因此克隆到 Leantime 时必须指定目标目录名 `CostTracking`
- fork 中 `app/Plugins/CostTracking` 现为指向该仓库的 **git submodule**（目录名保持 `CostTracking`，运行身份由目录名推导，与仓库名/包名无关）

已执行的操作（可复现）：

```powershell
# 1. 原插件目录撤出主仓库索引（保留磁盘文件）
git rm -r --cached app/Plugins/CostTracking

# 2. 临时挪走磁盘目录，空出路径供子模块克隆
Rename-Item app/Plugins/CostTracking CostTracking.__subtmp

# 3. 登记子模块。插件仓库尚未推送到 GitHub 时，用本地路径 + 允许 file 传输；
#    若远端已存在，直接把 URL 换成 GitHub 地址即可。
git -c protocol.file.allow=always submodule add E:/GhRepo/mr-leantime-costtracking app/Plugins/CostTracking
Remove-Item -Recurse -Force app/Plugins/CostTracking.__subtmp

# 4. 把子模块 URL 指向 GitHub 并同步到 .git/config
git config -f .gitmodules submodule.app/Plugins/CostTracking.url https://github.com/GavinCnod/mr-leantime-costtracking.git
git submodule sync app/Plugins/CostTracking
git add .gitmodules
```

说明：

- gitlink 记录的是插件仓库的提交 SHA（首次为 `61a5079`）。**在插件仓库推送前不要对它 amend/rebase**，否则 fork 指针会失配；已推送后需更新指针则进子模块 `git fetch && git checkout <sha>` 后 `git add app/Plugins/CostTracking`。
- 插件仓库内的 `README.md` / `CHANGELOG.md` / `LICENSE` / `patches/` / `.gitattributes` / `.gitignore` 均属子模块内容，主仓库不再单独跟踪。

### B2. 运维影响（重要）

- **clone / 构建必须拉子模块**：`git clone --recurse-submodules`，或克隆后 `git submodule update --init --recursive`。CI/Railway 若未显式 checkout submodules，`app/Plugins/CostTracking` 为空 → `deploy/Dockerfile.prod` 快照不到插件、`plugin_ensure.php` 找不到插件。
- **自动启用变量值随包名变更**：`LEAN_PLUGINS_ENABLE=leantime/costtracking` → `mindrose/costtracking`（逗号分隔多个）。
- **已部署实例刷新元数据**：部署新版本后执行 `php bin/leantime plugin:costtracking:sync-metadata`；切勿用卸载重装刷新元数据（`uninstall()` 会删 `zp_ticket_costs`）。
- 插件依赖的 4 个核心钩子补丁现随插件仓库发布（`patches/`），安装说明见插件仓库 README。

### B3. 改动后的 git 状态（提交前）

## E. 部署机制改动（让插件能进入持久化卷 / 支持 Railway）

背景：生产容器的 `app/Plugins` 是持久化挂载点，Docker 卷首次初始化后会遮蔽镜像内容；Railway 又没有 `docker exec` 入口。2026-09-14 增加以下部署侧改动（均为通用能力，不绑定 CostTracking 业务）：

| 文件 | 改动 |
|---|---|
| [deploy/Dockerfile.prod](../../deploy/Dockerfile.prod) | 新增两条 COPY：把源码插件快照到 `/opt/leantime/plugins.builtin/`，把 `deploy/plugin_ensure.php` 放到 `/opt/leantime/` |
| [deploy/entrypoint.sh](../../deploy/entrypoint.sh) | 新增 `sync_builtin_plugins()`（启动时把内置插件幂等同步进命名卷或 `/data/plugins`）与 `ensure_plugins()`（读 `LEAN_PLUGINS_ENABLE` 环境变量，启动 web 前幂等安装启用，DB 未就绪时 2s×30 重试）；同步/ensure 放在属主修正之前，保证 root 写入的缓存文件最后被 chown 回 www-data |
| [deploy/plugin_ensure.php](../../deploy/plugin_ensure.php) | **新增**。引导 Laravel Console Kernel 的一次性 PHP 脚本：扫描 `app/Plugins/*/composer.json` 建包名→目录映射，按包名查 `zp_plugins`——未注册才调 `Plugins::installPlugin()`（核心 `addPlugin` 不去重，不能裸跑 install）、未启用才 `enablePlugin()`；全部成功 exit 0 |

新增的环境变量：

| 变量 | 作用 |
|---|---|
| `LEAN_PERSIST_ROOT` | 已有：单卷模式根目录（Railway 设 `/data`） |
| `LEAN_PLUGINS_ENABLE` | 新增：逗号分隔的插件 composer 包名，启动时幂等安装启用，如 `mindrose/costtracking` |

详见 [04-安装与验证手册.md](04-安装与验证手册.md) §4.2 方式三 与 [.docs/initial-0910/11-构建测试与部署.md](../initial-0910/11-构建测试与部署.md) §11.7。
