## B. `.gitmodules` 修改：解除 app/Plugins 官方子模块

### 背景

upstream 把 `app/Plugins` 登记为指向官方商业插件私库的 git 子模块：

```ini
# 原 .gitmodules（已删除）
[submodule "app/Plugins"]
	path = app/Plugins
	url = git@github.com:Leantime/plugins.git
```

后果：Git 把整个 `app/Plugins` 当作一个 submodule gitlink，**插件文件无法加入主仓库提交**（`git add` 报 `Pathspec ... is in submodule 'app/Plugins'`）；且该私库无推送权限，子模块方式对自建 fork 不可行。

### 已执行的操作（可复现）

```powershell
# 1. 从索引移除子模块指针（保留磁盘文件，不要加 -f）
git rm --cached app/Plugins

# 2. 删除 .gitmodules（本仓库只有这一个子模块；若有其他子模块则只删除对应小节）
Remove-Item .gitmodules   # 本次操作等价于删除该文件

# 3. 清理 .git/config 中的子模块配置小节
git config --remove-section submodule.app/Plugins

# 4. 把变为普通目录的插件与 .gitmodules 删除一并暂存
git add app/Plugins .gitmodules
```

说明：

- 子模块本地从未 init 检出（`git submodule status` 前缀为 `-`，目录下无 `.git`），所以不需要 `git submodule deinit`，也无需清理 `.git/modules/app/Plugins`。若在其他环境该目录已初始化，还需执行：
  `git submodule deinit -f app/Plugins` 并删除 `.git/modules/app/Plugins`。
- `.gitignore` **没有**忽略 `app/Plugins`（仅有一条不相关的 `app/custom/plugin/`），解除后目录内文件直接被主仓库跟踪。
- 解除后 clone fork 即可得到插件，**不再需要** `git clone --recurse-submodules`。

### 改动后的 git 状态（提交前）

```text
D  .gitmodules                              # 删除
D  app/Plugins                              # 旧 gitlink 删除
A  app/Plugins/CostTracking/...（15 个文件） # 新插件作为普通文件纳入
 M app/Domain/Projects/Templates/partials/projectCard.blade.php
 M app/Domain/Tickets/Templates/partials/ticketCard.blade.php
 M app/Domain/Tickets/Templates/showKanban.blade.php
```

> ⚠️ 上游合并注意：未来从 upstream 合并时，若对方仍维护该 submodule，`.gitmodules` 与 `app/Plugins` gitlink 可能产生冲突，解决方式一律是**保留我方「删除」状态**（`git rm .gitmodules` / `git rm --cached app/Plugins` 后重新 add 插件目录）。详见 [05-持续开发指南.md](05-持续开发指南.md) §5.5。

## E. 部署机制改动（让插件能进入持久化卷 / 支持 Railway）

背景：生产容器的 `app/Plugins` 是持久化挂载点，Docker 卷首次初始化后会遮蔽镜像内容；Railway 又没有 `docker exec` 入口。2026-09-14 增加以下部署侧改动（均为通用能力，不绑定 CostTracking 业务）：

| 文件 | 改动 |
|---|---|
| [deploy/Dockerfile.prod](../../deploy/Dockerfile.prod) | 新增两条 COPY：把源码插件快照到 `/opt/leantime/plugins.builtin/`，把 `deploy/plugin_ensure.php` 放到 `/opt/leantime/` |
| [deploy/entrypoint.sh](../../deploy/entrypoint.sh) | 新增 `sync_builtin_plugins()`（启动时把内置插件幂等同步进命名卷或 `/data/plugins`）与 `ensure_plugins()`（读 `LEAN_PLUGINS_ENABLE` 环境变量，启动 web 前幂等安装启用，DB 未就绪时 2s×30 重试）；同步/ensure 放在属主修正之前，保证 root 写入的缓存文件最后被 chown 回 www-data |
| [deploy/plugin_ensure.php](../../deploy/plugin_ensure.php) | **新增**。引导 Laravel Console Kernel 的一次性 PHP 脚本：扫描 `app/Plugins/*/composer.json` 建包名→目录映射，按包名查 `zp_plugins`——未注册才调 `Plugins::installPlugin()`（核心 `addPlugin` 不去重，不能裸跑 install）、未启用才 `enablePlugin()`；全部成功 exit 0 |

新增的环境变量：

| 变量 | 作用 |
|---|---|
| `LEAN_PERSIST_ROOT` | 已有：单卷模式根目录（Railway 设 `/data`） |
| `LEAN_PLUGINS_ENABLE` | 新增：逗号分隔的插件 composer 包名，启动时幂等安装启用，如 `leantime/costtracking` |

详见 [04-安装与验证手册.md](04-安装与验证手册.md) §4.2 方式三 与 [.docs/initial-0910/11-构建测试与部署.md](../initial-0910/11-构建测试与部署.md) §11.7。
