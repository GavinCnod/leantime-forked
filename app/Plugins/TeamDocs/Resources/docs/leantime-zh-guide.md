## 1. 部署(管理员/维护者)

团队成员一般不用管这节 —— 你们用的系统已经部署好了。这节是给**维护系统的人**(你)看的。

- 生产部署:`deploy/docker-compose.prod.yml` + `deploy/Dockerfile.prod` + `deploy/entrypoint.sh`
- 反向代理 / TLS:`deploy/Caddyfile`
- 配置:`config/.env`(基准见 `config/.env.sample` 和 `deploy/.env.prod.example`)
  - 数据库连接、`LEAN_*` 系列变量
- 部署手册:`deploy/railway.md`(Railway)、`deploy/tencent-lighthouse.md`(腾讯云轻量)
- CostTracking 插件:已通过 `deploy/plugin_ensure.php` 随镜像内置，**不需要团队成员 `git apply` 打补丁**。若界面上没看到"成本"tab，先清 `storage/framework/views/*` 缓存(见[第 8 节](#8-常见问题))。

## 2. 首次登录与安装

- 浏览器打开 `登录域名`
- 首次进 `/install`，按向导建库、建第一个管理员账号
- 之后用邮箱/密码登录

- 右上角头像 → 语言(Language)→ 选**中文**
- 界面术语和团队用词对照，见 `docs/leantime-zh-glossary.md`
- 少数位置模板里写死了英文,中文界面下也是英文,见[第 9 节](#9-界面显示英文的位置不是-bug)

## 4. 建项目与拆任务

### 4.1 项目生命周期

项目(Project)是 Leantime 里装的**一件要完成的事**。任务是挂在项目下面的。

#### 4.1.1 新建项目

两个入口,任选:

- 顶部 **`所有项目(All Projects)`** → 右上角 **`新项目(New Project)`**
- 左上项目选择器 → **开始新的工作(Create something new)**;或项目枢纽 → `Create something new`(英文)→ **`创建项目(Create a Project)`**
  - 枢纽里的 **`创建战略(Create Strategy)`** / **`创建计划(Create Plan)`** 两个卡片需要额外插件,本 fork 未装,点开显示 `Not Available in this plan`

新建表单(`/projects/newProject`)只有一个页签「项目详情」:

| 字段 | 界面显示 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| 项目名称 | 占位文字「输入此项目的标题」 | **必填** | 留空报错「新增项目失败」 |
| 描述 | 「您想要完成什么？」 | 可选 | 富文本编辑器 |
| 项目日期 | 「开始日期」/「截止日期」 | 可选 | 项目整体的计划起止,不是任务的到期日 |
| 客户/产品 | 「客户/产品」 | **必填** | 下拉选已有客户;没有就点下面的「未列出客户？新增一个新客户。」(manager 及以上才显示该链接) |
| 访问范围 | 「谁可以访问此项目？」 | 可选 | 三选一,见 [4.1.4](#414-团队成员与权限) |
| 项目状态 | 「有效」/「已关闭」 | 可选 | 新建时保持「有效」 |
| 预估 | 「预估时间」/「预估成本」 | 可选 | 见下方说明 |
| 项目头像 | 「项目头像」 | 可选 | 上传方形图片 |

**关于两个"预估"字段**:它们就是项目预算,是 CostTracking 插件"`成本(Costs)`"页签里"项目预算"的来源。

- **「预估成本」= 金额预算**(元)—— 团队记账用这个。不填,成本页签会提示尚未设置金额预算。
- 「预估时间」= 工时预算(小时)—— 团队目前不用,可留空。

> [!NOTE]
> **不在新建表单里的东西**:团队成员(建完再进「团队」页签加)、父项目(本 fork 的核心没有父项目选择器,项目类型只有 `project` 一种,不存在项目嵌套)。
>
> 创建成功后会自动切到新项目并跳到项目设置页,提示「成功新增项目」。

#### 4.1.2 项目设置页的五个页签

进 `所有项目` → 点项目名,或从项目选择器进入,地址是 `/projects/showProject/{id}`。页面上有五个页签:

| 页签 | 地址锚点 | 里面有什么 |
| --- | --- | --- |
| 项目详情 | `#projectdetails` | 改名字、描述、起止日期、客户、访问范围、状态、预算、头像 |
| 团队 | `#team` | 加减成员、给成员设项目角色(见 [4.1.4](#414-团队成员与权限)) |
| 集成 | `#integrations` | Slack / Mattermost / Zulip / Telegram / Discord 的 webhook,以及项目级通知静音 |
| 待办事项设置 | `#todosettings` | 自定义这个项目的任务状态(见 [4.3.4](#434-按项目自定义任务状态)) |
| 成本 | `#costtracking` | CostTracking 插件挂的,见[第 5 节](#5-costtracking-插件使用面向团队成员无需安装) |

页面**右上角**还有两个按钮:`复制(Copy)` 和 `删除(Delete)`,按钮文字是英文,见 [4.1.6](#416-复制项目与删除项目)。

#### 4.1.3 设置项目预算

1. 进项目设置页 → **项目详情** 页签
2. 右侧「预估」一组里填 **「预估成本」**(金额)
3. 点 **保存**

没设预算时,成本页签会提示尚未设置金额预算,记账仍可进行但看不到"预算使用率/剩余/超支"。**团队项目请务必填。**

#### 4.1.4 团队成员与权限

进项目设置页 → **团队** 页签。

- **加人**:在「将其他用户分配给此项目」下勾选要加的人
- **减人**:把「当前团队成员」里对勾**取消**
- **改角色**:每个成员下面的下拉框,给这个成员**在这个项目里**的角色
- 改完点页面的保存按钮(中文界面下显示 **Save**,是英文)

角色选项:

| 下拉框显示 | 含义 |
| --- | --- |
| `Inherit`(英文) | 沿用这个人在公司层面的角色 |
| 只读 | 只能看 |
| 可评论 | 能评论、上传,不能改任务 |
| 可编辑 | 能建任务、改任务、记工时 |
| 公司经理 | 能改项目设置 |

管理员/所有者成员显示为只读文本,不能在这里降级。

访问范围(在项目详情页签设)决定**没被点名的人**能不能看见这个项目:

| 选项 | 含义 |
| --- | --- |
| 只有我在"团队"下选择的用户 | 只有上面团队页签里点名的人能看见(默认) |
| 分配给该客户的成员 | 该客户下的所有人都能看见 |
| 此组织中的成员 | 全公司都能看见 |

> [!WARNING]
> **保存团队是全量替换**:保存时系统会先删光这个项目的所有成员关系,再按页面上的勾选重新写入。所以:
>
> - 取消某个对勾 = 把那个人移出项目
> - 如果页面没加载完整(比如网络卡了)就点保存,可能导致成员被误删
>
> 改完确认一下「当前团队成员」列表对不对再离开页面。

> [!NOTE]
> 任务负责人(Assigned to)和项目成员是两回事:一个人可以**在项目里**但不负责任何任务,也可以**被指派任务**。项目访问权只看团队页签,不看任务指派。

#### 4.1.5 项目状态:有效 / 已关闭

项目详情页签 → 「设置」一组 → **「项目状态」**:

- **「有效」** = 正常进行中
- **「已关闭」** = 收尾。项目仍留在系统里,数据都在,只是标记为关闭

只有这两个值,项目**没有独立的"归档"功能**。

> [!TIP]
> **关闭项目不需要先清空任务**,系统不会拦你。
>
> 关闭后项目**仍会出现在「所有项目」列表里**,只是「状态」列显示「已关闭」。这是已知行为:「所有项目」页上那个 `Show Closed Projects` 勾选框(英文)目前不生效 —— 它存在会话里,但列表查询没读它。想看"只剩进行中"的清单目前只能按状态列自己看。

#### 4.1.6 复制项目与删除项目

两个按钮都在项目设置页**右上角**。

**复制项目**(按钮显示 `Copy`,英文):

点开 `/projects/duplicateProject/{id}` 弹窗,填:

- **「新项目名称」** —— 默认预填「(复制) 原名」
- **「计划开始日期」** —— 默认今天
- **「客户/产品」**
- 勾选 **「分配相同成员」** —— 勾上则把成员一起复制过去

**会复制**:项目本身(名称、客户、状态、描述、预算、访问范围)、这个项目的任务状态设置、所有任务(**日期会按新旧起始日的差值整体平移**)、想法板、目标画布、百科、精益画布。

**不会复制**:评论、文件附件、工时记录、日历事件。

> [!TIP]
> 复制项目适合"同类项目再来一遍"——比如给新客户做和上个客户一样的交付流程。复制完记得检查任务日期对不对,以及有没有混进上个客户的内容。

**删除项目**(按钮显示 `Delete`,英文):

点开 `/projects/delProject/{id}` 确认页 → 确认删除。

> [!CAUTION]
> **删除项目 = 连项目下的所有任务一起删,不可撤销。**
>
> - 如果项目里还有任务,系统会先提示「无法删除项目；此项目中仍有待办任务，请先删除所有待办任务」
> - 删完会切回「所有项目」并提示「项目已删除」
>
> **想留档就改用「已关闭」,不要删除。**

### 4.2 任务生命周期

任务是 Leantime 的核心工作单元,界面上叫「待办任务(To-Do)」;数据层叫 Ticket,所以有些提示语会写"工单"(如删除确认页的「确定删除此工单？」)—— **工单 = 任务**,同一个东西。

#### 4.2.1 新建任务

| 入口 | 能填什么 |
| --- | --- |
| 左侧「**待办事项**」页面 → **`新增待办(New To-Do)`** 按钮 | 完整表单(推荐) |
| 看板视图某一列顶部的快速新增框 | **只有标题**;标签是英文(`Add To-Do`、`What are you working on?`) |
| 列表视图左侧输入框 | 只有标题 |
| 仪表盘「📥 我的待办任务」小工具 | 标题 + 项目 |
| 项目仪表盘 → `Create To-Do`(英文) | 只有标题 |

> [!NOTE]
> 快速新增框**选不了负责人、到期日、状态** —— 建完要点进任务详情补。数量少就走完整表单,别事后补一堆。
>
> ⚠ **「新增待办」按钮只在「列表」视图里有**;看板视图要靠列顶部的快速新增框。

完整表单(任务详情弹窗)的字段:

**必填只有一个:「标题」**(占位文字「输入待办任务的标题」)。其余全可选。

上半部分(默认展开):

| 字段 | 界面显示 | 说明 |
| --- | --- | --- |
| 标题 | (无标签,占位文字) | **必填** |
| 状态 | 「状态」 | 见 [4.2.3](#423-状态流转) |
| 优先级 | 「优先级」 | 1–5 |
| 工作量 | 「工作量」 | 工作量点数(story points) |
| 分派给 | 「分派给」 | 单人;旁边有「分派给我」快捷链接 |
| 协作人 | `Collaborators`(英文) | 多选。选了负责人后,这个人会自动从协作人里去掉 |
| 到期日 | 「到期日」 | 日期 + 时间 |
| 标签 | 「标签」 | 自由文本 |
| 描述 | (无标签) | 富文本编辑器 |

下半部分「组织」/「排期」(需展开):

| 字段 | 界面显示 | 说明 |
| --- | --- | --- |
| 类型 | 「类型」 | 选项显示为「任务 Task」/「子任务」/「故事 Story」/「缺陷 Bug」—— 前三个是中英混排,子任务只有中文 |
| 项目 | 「项目」 | 归属项目 |
| 里程碑 | 「里程碑」 | 可选「未绑定里程碑」 |
| Sprint 冲刺 | 「Sprint 冲刺」 | 可选「Backlog 待办任务列表」= 不进任何迭代 |
| (依赖某一任务) | 「相关于」 | 见 [4.3.3](#433-任务之间设置前置依赖) |
| 工作开始 / 工作结束 | 「工作开始」/「工作结束」 | 计划施工时间窗,时间轴上用 |
| 计划时数 / 预估剩余时数 | 「计划时数」/「预估剩余时数」 | 与第 5 节的成本是两套独立数字 |

底部按钮:「保存」/「保存并关闭」。

> [!WARNING]
> **「类型」选「子任务」不会让它变成子任务。** 父子关系由"从哪里创建"决定(见下条),类型下拉只是个分类标签。

#### 4.2.2 子任务

在**任务详情弹窗**里往下拉到「子任务」区 → 点新增 → 填标题 → 保存。

- 子任务**只有一个层级**,子任务下面不能再挂子任务
- 子任务自动继承父任务的项目和里程碑;状态默认「新增」、负责人默认当前用户,建完可以改
- 看板上子任务**也显示为一张卡片**,并标注父任务名
- 只有弹出任务详情才能加子任务;小工具里的 `Add Subtask`(英文)也可以,但字段更少

> [!TIP]
> 官方建议单个子任务控制在 4 小时以内。子任务**默认不计入**成本页签的统计 —— 那个页签默认只看"顶层任务"。

#### 4.2.3 状态流转

界面默认的六种状态:

| 界面显示 | 归类 | 说明 |
| --- | --- | --- |
| 新增 | 未开始 | 新建任务的默认状态 |
| 已取消 | 进行中 | ⚠ 实际含义是**被阻塞/搁置**。中文译名易误读成"这个任务被取消了",看到别慌,任务没删 |
| 进行中 | 进行中 | 正在做 |
| 待批准 | 进行中 | 做完等确认 |
| 完成 | 已完成 | 视为完工 |
| 已归档 | 已完成 | **不在看板的列里**,只能通过状态下拉选到 |

流转方式:

- **看板视图**:直接把卡片从一列拖到另一列 ← 最常用
- **看板卡片 / 表格行 / 子任务行**:点状态下拉改
- **任务详情弹窗**:点「状态」下拉改

> [!WARNING]
> **同一状态在界面不同位置译名不一致**:任务状态下拉、看板列上显示「**已取消**」,但**项目设置页 →「待办事项设置」**
> 里同一个状态显示「**已锁定**」。两个指的是同一个"阻塞"状态,不是两种状态。
>
> **原因**(维护者看):状态设置页读的是数据库里的标签副本,而任务界面在项目未自定义过状态时读语言文件
> (`zh-CN.ini` 里 `status.blocked` = 「已锁定」,`label.status_blocked` = 「已取消」)。
>
> ⚠ 由此带来一个副作用:**改语言文件不会改变已有项目的状态名** —— 某个项目只要在「待办事项设置」里保存过
> 一次,状态名就固化进数据库了,之后改翻译也不生效。要改这类项目的状态名,得在项目设置页里手动改。
>
> **状态名和数量是每个项目可以自定义的**(见 [4.3.4](#434-按项目自定义任务状态)),所以别的项目里"状态 3"可能
> 根本不是「新增」。跨项目对状态时以**名字**为准,别记数字。

没有"固定走完的流程"——任何状态都能直接跳到任何状态,也不需要审批。

#### 4.2.4 里程碑

里程碑(Milestone)是**带起止日期的项目阶段**,它本身也存放在任务表里,但默认不出现在任务列表。

**创建**:左侧「**里程碑**」页 → 「新增」按钮下拉 → **`新增里程碑(Add Milestone)`**。

(⚠ 里程碑**没有独立的页签**可选,只能从这个「新增」下拉里进。)

里程碑表单字段:

| 字段 | 界面显示 |
| --- | --- |
| 标题 | 「里程碑标题」 |
| 项目 | 「项目」 |
| 状态 | 「状态」 |
| 前置依赖 | 「前置依赖」 |
| 拥有者 | 「拥有者」 |
| 颜色 | 「颜色」 |
| 计划开始日期 / 计划结束日期 | 「计划开始日期」/「计划结束日期」 |
| 成果与影响 | `Outcome & Impact`(英文) |

**给任务挂里程碑**:任务详情弹窗的「里程碑」下拉,或看板卡片上的里程碑下拉。

> [!NOTE]
> **里程碑进度不是按任务个数算的**,而是按「工作量 × 优先级」加权 —— 所以做完 3 个小任务,进度条可能只动了一点点。

#### 4.2.5 任务的几种视图

左侧「**待办事项**」页顶部可在几种视图间切换:

| 视图 | 界面显示 | 适合 |
| --- | --- | --- |
| 看板 | 「看板模式」 | 日常推进;拖拽改状态 |
| 表格 | 「表格模式」 | 批量看、按列筛 |
| 列表 | 「列表」 | 最简;也是唯一有「新增待办」按钮的视图 |

左侧「**里程碑**」页的视图:

| 视图 | 界面显示 | 适合 |
| --- | --- | --- |
| 时间轴 | 「时间轴」 | 甘特图;看依赖箭头、拖拽调日期 |
| 表格 | 「表格模式」 | 里程碑总表 |
| 日历 | 「日历」 | 按日期铺开 |

另外:**仪表盘首页的「📥 我的待办任务」小工具** = 分派给你的、还没完成的任务,可按到期日/项目/优先级分组(分成逾期 / 本周 / 之后三档)。新人每天的起点基本就是这个。

> [!TIP]
> 左侧菜单点「待办事项」会**回到你上次用的那个视图**,不一定是你想要的看板。找不到看板就点页顶的「看板模式」。

### 4.3 进阶功能(新人可以先跳过)

#### 4.3.1 Sprint 冲刺与 Backlog

Sprint 是给任务分批次用的,**只是分类,不改变看板本身**——"Sprint 看板"就是把看板按某次迭代筛一下,没有独立页面。

- **建迭代**:任务页顶部页头菜单 → **`创建迭代(Create Sprint)`**;填「Sprint 冲刺名称」「项目」「起始日/结止日」
- **把任务放进迭代**:任务详情弹窗的「Sprint 冲刺」下拉,或表格视图里的 Sprint 下拉
- **不属于任何迭代** = 「Backlog 待办任务列表」
- 页头的切换器可在「所有待办任务」/「Backlog 待办任务列表」/各个迭代之间切

#### 4.3.2 时间追踪(工时)

任务详情弹窗的「**时间追踪**」页签:

- 记录工时:填「类型」「日期」「时数」「描述」→ 保存
- 下方显示「计划时数」「已登记时数」「实际剩余时数」
- 也可以在看板卡片 / 任务详情上用「**开始工作**」跑秒表,再「停止工作」

> [!IMPORTANT]
> **工时和成本是两套独立的东西。** 记工时**不会**影响 CostTracking 的成本数字,填"实际成本"也**不会**生成工时记录。记账请按第 6 节走。

#### 4.3.3 任务之间设置前置依赖

任务详情弹窗的「**相关于**」下拉 → 选一个前置任务。依赖关系会在**时间轴(甘特)视图里画成箭头**,其他视图看不出来。

#### 4.3.4 按项目自定义任务状态

项目设置页 → **「待办事项设置」**页签。每一行是一个状态,可以改:

- 名称、排序(拖动)、颜色、在报告里算哪一类(新增/进行中/已完成/不报告)、是否在看板上显示
- 点「新增状态」加一个
- **「已归档」那一行是固定的**:不能改名、不能删、不在看板上显示

也可以在看板列的「⋮」菜单里点「编辑标签」改单个状态名。

> [!TIP]
> 团队如果要加"待客户确认""已交付"这类中间状态,就在这里加,加完看板会多一列。

#### 4.3.5 项目集成与其他

- **集成**:项目设置页 →「集成」页签,配 Slack / Mattermost / Zulip / Telegram / Discord 的 webhook,让项目通知推到群里
- **收藏项目**:项目枢纽页卡片上的星标 —— 收藏的项目会出现在项目选择器的「收藏」里
- **项目状态更新(红黄绿)**:项目仪表盘右栏「项目更新」→「新增状态更新」,选「进展正常」/「存在风险」/「严重风险」+ 说明。卡片上的小圆点就是这个
- **报表**:左侧「报告」,含「状态报表(Status Report)」和「交付衡量指标(Delivery Metrics)」两个页签

### 4.4 常见变更场景

#### 换任务负责人

任务详情弹窗 → 改「负责人」下拉。要改**协作人**必须走完整表单(看板卡片上改不了协作人),且**保存前先取消旧的、再加新的**。

#### 把任务移到别的项目

任务卡片「⋮」菜单 → **`移动待办(Move To-Do)`** → 选目标项目 → 移动。

(⚠ 里程碑也能移动:「⋮」→「移动里程碑」,并会**带上它关联的所有任务**。)

#### 复用上一个项目的结构

用**复制项目**,不要手工重建。见 [4.1.6](#416-复制项目与删除项目)。

> [!WARNING]
> **任务没有"复制"功能。** 想复用单张任务只能手动重建。

#### 项目做完了

- **只是不再推进** → 改「项目状态」为「已关闭」。数据全在,随时能翻账(成本页签仍可看)。
- **确认不要了** → 删除项目。**会连所有任务一起删,不可撤销。**

## 5. CostTracking 插件使用(面向团队成员，无需安装)

CostTracking 已随 fork 部署内置，**团队成员不需要安装、不需要打 patch**(那是维护者的活)。

你要做的只有:

1. **记成本**:在任务上填两个字段
   - **预算成本(planned cost)**:这件事预计要花多少(可选)
   - **实际成本(actual cost)**:实际花了多少 ← **记账就填这里**，备注格式见 `docs/cost-tracking-rules.md`
2. **看预算 vs 实际**:进项目页 → 点与"项目详情/成员"等并列的 **"成本"tab**，看预算使用率、预算剩余、超支金额、含成本任务数;可切"顶层任务/子任务"两个统计范围
3. **看板/列表上的成本**:任务卡片、任务表右侧有成本列(需要已打核心补丁，fork 已内置);简单列表里任务标题旁有成本角标

## 6. 费用记录操作(对照规矩)

产生一笔费用后:

1. 确认你是这笔的**经手人**(下单/付款的人)，不确定就群里 @ 相关人
2. 找到对应任务(客户沟通费→客户项目;样品费→下单项目;分摊/内部开销见规矩文档)
3. 打开任务 → 填"实际成本" → 备注写 `{月-日} {费用类型} 垫付 {发票号}`
4. 分摊:每个相关项目各记一笔，备注写"分摊自 {费用} {份额}"
5. 内部开销:进"内部开销"项目的固定"费用登记"任务上记

对照 `docs/cost-tracking-rules.md` 的 worked example。

## 7. 负责人每月核对

对每个项目:

1. 每个项目 → "成本"tab
2. 看三数字:预算使用率 / 预算剩余 / 超支金额
3. 切"子任务"范围看分摊细节
4. 异常(超支 / 归属存疑 / 大量补记)当场群里 @ 经手人改
5. 各经手人口头报本月发票号，听有没有记重(当前插件无法跨任务看备注，去重靠这一步)

## 8. 常见问题

- **界面上没"成本"tab / 成本列不显示**
  管理员清缓存:`rm -rf storage/framework/views/* && rm -f storage/framework/viewPaths.php`，再刷新。团队成员遇到直接报给维护者。
- **PostgreSQL 下成本数字不对**
  本 fork 已修 Postgres 兼容性(commit `358679109` / `0c4e8835b` 等)。若你用的不是 Postgres 可忽略;是 Postgres 且异常，查 `app/Core/Db/DatabaseHelper` 相关。
- **插件卸载会删表**
  `plugin:remove mindrose/costtracking` 会 drop `zp_ticket_costs`，**先备份数据**。禁用(`plugin:disable`)不删表。
- **成本字段填了但汇总没变**
  确认填的是"实际成本"(不是预算成本);统计范围选的是不是"顶层任务";子任务上的成本要在"子任务"范围才计入。
- **改 composer.json 元数据不生效**
  Leantime 只在安装时读一次 composer.json。部署新元数据后跑 `php bin/leantime plugin:costtracking:sync-metadata`。
- **界面上某处是英文**
  先看[第 9 节](#9-界面显示英文的位置不是-bug):少数几处是模板写死的,改不了;如果其他地方也变英文了,多半是语言缓存过期,让维护者清缓存。

## 9. 界面显示英文的位置(不是 bug)

以下位置在**中文界面下仍显示英文**,因为模板里把文案直接写死了(没有语言键),任何语言文件都改不了:

| 位置 | 显示的英文 |
| --- | --- |
| 「所有项目」页右上 | `Show Closed Projects`(⚠ 该勾选框目前不生效,见 [4.1.5](#415-项目状态有效--已关闭)) |
| 项目设置页右上按钮 | `Copy` / `Delete` |
| 看板快速新增框 | `Add To-Do` / `What are you working on?` / `Save` / `Cancel` |
| 看板卡片 / 小工具菜单 | `Add Subtask` |
| 项目仪表盘右上 | `Create To-Do` |
| 待办事项页的筛选栏 | `Filter` / `Group By` / `All Users` / `All Statuses` / `Show Tasks` |

> [!WARNING]
> **「删除项目」按钮的悬停提示会显示原始键名 `link.delete_project`。** 这是那唯一的真·缺键:模板引用了
> `link.delete_project`,但 en-US 和 zh-CN 两个语言文件里都没有这个键,所以界面上直接把键名当文案显示了。
> (旁边的「复制项目」工具提示正常,因为 `link.duplicate_project` 存在。)

### 如果"该显示中文的地方却是英文"

**那不是翻译缺失,是语言缓存过期。** 语言文件改动后必须清缓存才生效,否则系统一直用旧的一份:

```bash
rm -rf storage/framework/cache/data/*
rm -rf storage/framework/views/*
rm -f storage/framework/viewPaths.php
```

清完刷新页面。团队成员不用自己动手,报给维护者即可。

> [!TIP]
> 遇到看不懂的界面文字,先查 `docs/leantime-zh-glossary.md`,查不到报给维护者。
>
> 维护者注意:判断"某处是不是缺翻译"之前,先 `grep -rn "键名" app/` 确认那个键**真的被模板引用**且**真的不存在**。
> 本指南早期版本曾把三处**本来就已翻译**的位置(项目第一个页签、团队页保存按钮、任务弹窗标题)误列为翻译缺口,
> 实际它们分别调用了 `tabs.projectdetails`、`buttons.save`、`headlines.new_to_do`,中文语言文件里都有值。
